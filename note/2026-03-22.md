## 1 Setup: Creating the Dictionary
Before your Decoder can do anything, you need a reference library. 
1.  Take every sentence you might ever want your model to "say."
2.  Pass them through your `gemma_encoder`.
3.  Store these resulting vectors in a **FAISS Index**. 

Notably we have two distinct cases:
- training
- prediction

At training time the FAISS library is not needed as we only need to train the
decoder.
Noting that the problem is defined so that the output is in the input, but we
insert it back in just in case.

At inference time, we actually use the model to make prediction on data we don't
really know, and thus we need the FAISS to convert the predicted embedding into
words.

## 2 Encoder: Text to Embedding
Use embeddinggemma to convert the input into embeddings. The model is defined in 
@src/model/encoder.py

All the training dataset is converted, then the training starts, to save
computation and avoid computing the embedding twice.

Basically for each sample there shall be:
1. embeddings of the input
2. embeddings of the output (to compute the loss)
3. standard tgt for every imput, i.e. encoding of the boilerplate:
   ```
   Pieces:
   Manufacturer:
   ...
   ```

The dataset is to be fetched through load_dataset in @src/data/util.py setting:
- dataset_variation = SIMPLE_DIFFUSION
- split ratio = 0.5, 0.1, 0.4

## 3 Decoder: Generating the prediction
The `Decoder` in @src/model/decoder.py predicts a list of embeddings
* **Input:** embeddings of the input (the `memory`).
* **Output:** A list of vectors each of the dimension of embedding gemma 
  embeddings (i.e. 768).

Namely tgt shall be the something like:

```
Pieces:
Manufacturer:
...
```

## 4. The Retrieval: Converting the Vector to Text
This is where the Nearest Neighbor logic happens. Once the Decoder outputs a list of vectors, you do the following:

1.  **Normalization:** You scale the predicted vector so its length is 1.
2.  **The Search:** You you search the vector in FAISS. FAISS looks at all the stored tokens and asks: *"Which of my stored vectors is mathematically closest to this new one?"*
3.  **The Result:** FAISS returns the index of the closest match. You look up that index in your list of tokens

## 5. Summary of the Flow

1.  **Training Phase:** You train the Decoder to produce vectors that are as close as possible to the real Gemma embeddings of your target text (using a Loss Function like MSE or Cosine Similarity).
2.  **Inference Phase:** * **Input Data** $\rightarrow$ **Decoder** $\rightarrow$ **Predicted Vector**.
    * **Predicted Vector** $\rightarrow$ **FAISS Search** $\rightarrow$ **Closest Sentence Found**.
